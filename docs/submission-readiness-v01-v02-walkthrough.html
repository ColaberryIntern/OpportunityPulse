Submission Readiness v0.1 + v0.2

Visual walkthrough · captured against prod 95.216.199.47 · 2026-05-08

The screenshots below are full-page captures from prod taken just after the v0.2 deploy (commits e1bace3 + 38119a0). Click any screenshot to zoom. Each section has a feedback box; click Copy all feedback at the bottom and paste back when you've worked through the doc.

Heads up on visual fidelity: prod's Document Vault is empty (no docs uploaded yet) and the existing Bonfire scraper only captures titles, not RFP narrative — so AI runs against sparse description text and correctly returns 0 additional flags. The screens below show the real, current state. The last section adds a CSS mockup of what the panel looks like with AI flags + uploaded vault docs so you can critique that layout too.

Context — what changed visually

The two ships introduce five new visual surfaces:

  1. Sidebar: new 📁 Document Vault link under Operate.
  2. Document Vault page at /admin/documents: summary cards, type-grouped table, upload modal.
  3. Bonfire table: new Readiness column with inline progress bar per row.
  4. Bonfire detail panel: Submission Readiness card with completion %, status pills, vault deep-links.
  5. Bonfire detail panel — AI section: 🤖 Tailor with AI button, AI summary banner, source pills (🤖 AI / ⚡ rule), inline RFP-quote blocks.

Plus: 11 new document-type entries in the upload modal's type picker (bid bond / payment bond / performance bond / Davis-Bacon / EEO / professional licensure / safety program / cybersecurity / site visit ack / addendum ack / non-collusion affidavit).

2 · Document Vault — empty state

Path: /admin/documents · admin-only

First load. Four summary cards at the top (Active / With expiry tracked / Expiring ≤30d / Expired) plus the empty-state copy nudging you to upload your first evergreen file.

What to look for

  • Header: "📁 Document Vault" + a small v0.1 pill.
  • Subtitle calls out the Bonfire link explicitly so you know why uploading helps.
  • 4-card summary stays even when empty — easier to read once docs land.
  • Type-filter dropdown above the (empty) table.
  • Upload button (top right) is the call-to-action.
Empty-state feedback — copy, layout, hierarchy, missing affordances?

3 · Document Vault — upload modal

Triggered by clicking + Upload document

The type picker is the most-decision-laden control on this screen — it carries 18 canonical types (W-9, Capability Statement, COI, Past Performance, Key Staff Resume, NAICS List, References, 8(a) / HUBZone / WOSB / SDVOSB / MWBE certs, SAM Registration, Banking, plus 11 v0.2 additions like bid bond, prevailing wage, EEO, etc.). The expiry date is optional but tracked for renewal reminders.

What to look for

  • Type picker pre-populated with the canonical 18 types.
  • File picker accepts PDF, DOCX, DOC, PNG, JPG, TXT (≤25 MB).
  • Display name auto-fills from filename if left blank.
  • Expiry date as a native HTML date picker (renews remembered for COIs etc.).
  • Cancel + Upload buttons aligned right.
Upload modal feedback — types missing, fields missing, copy?

4 · Bonfire table — Readiness column

Path: /bonfire

A new Readiness column sits between Close date and Signals. Each row shows a completion % and a sliver progress bar — driven by a single bulk endpoint that returns { id → { completion_pct, satisfied, total, gaps } } for the visible page only.

What to look for

  • Every row is at 17% — that's "1 of 6 baseline docs satisfied" against the empty vault. (References is the one that's already accounted for via existing data.)
  • Bar color follows priority ramp: ≥80% green · ≥60% yellow · ≥30% orange · <30% red.
  • Hover tooltip: 1/6 required docs on file · 5 gaps.
  • The column is admin-only — non-admin viewers don't see it (the bulk endpoint is gated on auth + role).
Table feedback — column placement, bar styling, color choices?

5 · Bonfire detail panel — baseline (before AI)

Triggered by clicking any row title in the Bonfire table

The detail drawer slides in from the right. The Submission Readiness card is the first thing under "What this is" — completion % at the top, gap counter as a red pill, progress bar, then the 6-item baseline checklist with status pills + Upload deep-link for any gaps.

What to look for

  • Card header: "Submission Readiness" + version pill (here: v0.1 · baseline) + count "1 of 6 required docs ready" + the 🤖 Tailor with AI button.
  • Big 17% + complete + 5 gaps badge.
  • Six checklist items: ✓ On file (References), ✗ Missing (the rest).
  • Each missing item has a blue Upload → link that jumps to the vault.
  • Footer line at the bottom: "Click 'Tailor with AI' to detect bid-specific requirements" + Manage documents →.
Baseline panel feedback — copy, status pills, layout density, anything missing?

6 · Bonfire detail panel — after clicking 🤖 Tailor with AI

Same panel after the AI call completes (~2–3s)

Clicking 🤖 Tailor with AI fires Claude on the opp text. On THIS prod row the description is empty (Bonfire scraper currently only captures titles), so AI correctly returns 0 additional flags with the summary "This RFP does not specify any additional document requirements beyond the standard baseline." The visible diff is small but real: header pill flips to v0.2 · AI-tailored, the AI summary banner appears, and the button label switches to 🤖 Refresh AI.

What to look for

  • Header pill flips from v0.1 · baseline → v0.2 · AI-tailored.
  • Button label: 🤖 Refresh AI (was 🤖 Tailor with AI) — clicking re-runs even with cache.
  • Footer line shows AI run: <timestamp> · 0 additional flagged.
  • Result is cached on the row — next visit skips the AI call.

Because prod's Bonfire scraper only captures titles, you don't see the AI's real value here — the flagged-requirement layout. What this mockup shows

  • Source pill on each AI-flagged row: small "🤖 AI" tag next to the type label so you can tell baseline (no pill) vs AI-detected.
  • RFP-quote block: small italic reason on top + a "RFP says: '…'" quote underneath, blue left-border. The quote is mandatory at the validation layer — items without it are dropped before they hit the panel.
  • Mixed states: ✓ On file, ⚠ Expiring (with days-until counter), ✗ Missing — all in one list so you can scan compliance at a glance.
  • AI summary banner at top is the human-readable version of what the AI thinks this RFP needs. Helps users sanity-check whether AI understood the RFP correctly.
  • Footer: AI run timestamp + count of additional-flagged so you know cache freshness.

Final notes & feedback

All visuals above are live in prod right now (or the mockup represents what the same component renders with rich data). To unlock the full v0.2 visual experience on real bids, two things need to happen:

  1. Upload evergreen docs at /admin/documents — capability statement, COI, references at minimum. The %s on every Bonfire row will jump.
  2. Land Phase 2 of the master plan (per-opp Bonfire detail-page scraping with attachment download). Once Bonfire opps carry real RFP text, AI will start flagging bonds, prevailing-wage clauses, MWBE preferences, etc. — with quoted evidence — and the panel will look like the mockup in section 7.
