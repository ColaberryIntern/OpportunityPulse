Cross-cutting gaps

Patterns that show up across multiple features. Worth fixing once instead of feature-by-feature.

1. No Zod / JSON Schema validation at request boundaries

CLAUDE.md: "every public surface validates request body, query, and params before reaching business logic. Reject malformed input with 400 before any service code runs."

Routes accept req.body straight through. Controllers do light type-coerce (String(...), Number(...)) and conditional fallbacks (req.body.metadata = JSON.parse(...) ?? {}). The structural protection CLAUDE.md asks for — schema rejection at the route boundary — doesn't exist. Risk is low for admin-only endpoints; would matter more if any of these become public.

Fix path: Add Zod (~50KB dep), define schemas next to each route, mount as middleware. ~6–10h to retrofit across the 12 admin endpoints added in this run.

2. Observability per-operation tags

CLAUDE.md: "Every operation emits at start, end, and on error: correlation_id, operation, duration_ms, status, error_class, attempt."

Most logger.info/warn/error calls use ad-hoc context shapes per feature. correlation_id doesn't propagate. duration_ms isn't emitted on completion. Harder to trace a single request across services or build success-rate / latency metrics.

Fix path: Add an Express middleware that mints a correlation_id per request and exposes it via req.correlationId. Wrap logger in a small helper (logger.opStart('foo') → returns a closure that emits start + measures duration on end). ~4–6h to retrofit; ongoing discipline to use it.

3. autonomy_log.json writer is unbuilt

CLAUDE.md: "every change appends one entry to /tmp/autonomy_log.json ... until that writer ships, include the same information in the commit message body and PROGRESS.md note."

The substitute path (commit body + PROGRESS.md) has been followed consistently. The writer itself doesn't exist. If you want machine-readable autonomy logs (analytics, weekly digests), the writer is a small script: appends a JSONL line per commit using info already in the commit message + git stat.

Fix path: ~2–4h. A post-commit hook or a CI step that parses the latest commit and appends to /tmp/autonomy_log.json.

4. Build-Break-Harden — explicit BREAK phase missing

CLAUDE.md: "BUILD: implement happy path. BREAK: actively simulate failure (missing input, network drop, partial write, double-submit). HARDEN: add what BREAK exposed."

Failure-path tests exist for most features (e.g., AI returns non-JSON, opp not found, expired docs, retry logic). What's missing is the explicit BREAK phase as a checklist before shipping. Symptom: v9.9 needed two follow-up commits (9417c23, 26cd3a4) to render [object Object] errors properly — that should have been caught in BREAK.

Fix path: Add a 6-line BREAK checklist to the PR template: malformed input, missing fields, network timeout, double-submit, partial write, concurrent access. Cost: 0 engineering hours; pure process.

5. Failure-First Design — failure modes not documented per module

CLAUDE.md: "Every module declares failure modes, retry strategy, recovery path, and failure state."

Modules have try/catch + sensible fallbacks, but the declaration of failure modes — a header comment listing what can go wrong and what happens when it does — is inconsistent. v9.10 (sourceHealthAgent) does this well; most others don't.

Fix path: Standard 4-line header block on every new service file: Failure modes / Retry strategy / Recovery path / Failure state. Adopt going forward; don't backfill.

Are these the right gaps to prioritize? Anything I missed?

Recommendations (in priority order)

  1. Add Zod validation to admin routes (~6–10h). Highest-leverage gap. Blocks bad input at the route boundary instead of leaking into services. Start with the 4 routes added this week (/documents, /data-sources, /source-health-agent, /bonfire/.../tailor-requirements).
  2. Wire correlation_id middleware (~4–6h). Mint per request, expose via req.correlationId, thread into logger helper. Retrofit existing logger calls to use the helper.
  3. Adopt the 4-line Failure-First header on new service files going forward. Zero cost; pure discipline.
  4. Add a BREAK checklist to the PR template. Process change, no code. Would have caught the v9.9 error-rendering miss.
  5. Build the autonomy_log.json writer (~2–4h). Optional but unlocks weekly autonomy reports.
  6. Add unit tests for document.service and titleEmoji.js (~2h). Backfill the two known test gaps in this run.

Total: ~14–22h to close the systemic gaps. Worth doing before the next major feature push.
