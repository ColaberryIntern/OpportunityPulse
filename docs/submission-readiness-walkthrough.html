The problem today

Picture a typical Wednesday. A SAM.gov notice lands in your dashboard — a $250k healthcare data analytics RFP from the Defense Health Agency. The shortlist looks great. Now what?

What the human does today

  1. Open sam.gov/opp/{noticeId}/view in a browser, scroll to the Resources tab, download the SOW PDF + Q&A + amendment 1, save them to a folder named "DHA RFP — final.zip v3 ACTUAL".
  2. Open OneDrive, search for "capability statement," find three versions, pick the most recent one, copy it locally. Repeat for COI, W-9, past performance docs, key staff resumes.
  3. Read the SOW. Build a compliance matrix in Excel by hand: section 4.2.1 wants past performance with X / 4.2.3 wants Y / 4.3 wants pricing in Z format. Cross-reference against what's on hand. Note the gaps.
  4. Realize the COI expired six weeks ago. Email the broker. Wait two days for the renewal.
  5. Open Word. Draft the technical proposal. Paste in past-performance bullets from old proposals. Tweak. Tweak again. Have a colleague red-team. Tweak again.
  6. Convert to PDF. Combine all attachments into a single ZIP per the RFP submission instructions. Upload to SAM.gov. Click Submit.

Industry sources put a small-vendor federal bid at 8–23 hours. A grants.gov application at 20–40 hours. A Bonfire RFP at 4–8 hours. The bulk of that time is in steps 1, 2, 3, and 6 — document hunting, compliance checking, format conversion, package assembly. Steps 4 and 5 are where real strategic value gets created.

The vision

A five-stage pipeline behind every shortlisted opportunity. The first three stages run autonomously overnight; the last two are one-click humans.

1 · Ingest

Already done. Opp Pulse pulls from SAM.gov, grants.gov, Bonfire scraper, plus 19 other sources daily.

Live
→

2 · Vault

Org-wide evergreen document store: W-9, COI, capability statement, past performance, certs, resumes. Versioned, expiry-aware.

Phase 1
→

3 · Locker

Per-opportunity attachment locker: auto-downloads SOW, Q&A, amendments, agency forms.

Phase 2
→

4 · Matrix

AI-generated compliance matrix: every RFP requirement → satisfied or gap.

Phase 3
→

5 · Package

One-click ZIP: drafted proposal + cover letter + budget + every required evergreen attachment, ready to upload.

Phase 4

A sixth phase wraps it all in a human-friendly Submission Readiness page (gaps, expiries, one-click "fix this," mark-submitted with confirmation receipt upload). A seventh phase plugs the evergreen vault back into proposal generation so drafts cite real artifacts rather than inferring from the org profile.

What lives where, by the numbers

  • Documents (vault): ~10–15 evergreen artifacts per org, refreshed annually or on change.
  • Attachments (locker): ~3–15 files per opp; large ones in the SAM.gov / grants.gov set.
  • Compliance matrix: 10–40 rows per opp, regenerated whenever attachments change.
  • Submission packages: generated on demand; not persisted as binary, regenerated from constituent parts.

Use case 1 · SAM.gov federal contract

Scenario: CQuvator (Colaberry's federal vehicle) responds to a Defense Health Agency RFP for a $250k "AI-Assisted Healthcare Data Analytics Platform". NAICS 541512. Set-aside: small business. Response deadline: 14 days.

Today — 18 hours

  • Day 1 (3h) — Open sam.gov, hunt the Resources tab, download SOW + 2 amendments + Q&A. Skim. Build folder structure manually.
  • Day 1 (2h) — Search OneDrive for capability statement, COI, W-9, past performance docs, NAICS list. Pick latest versions. Realize COI expired 6 weeks ago. Email broker.
  • Day 2 (2h) — Read the SOW carefully. Build compliance matrix in Excel. Cross-check against profile + on-hand docs.
  • Day 2–3 (4h) — Draft tech proposal. Paste/adapt past-performance bullets.
  • Day 3 (2.5h) — Pricing model. Labor categories, rates, profit.
  • Day 3 (2h) — Tailor 3 past-performance narratives to this RFP's evaluation criteria.
  • Day 4 (1.5h) — Red-team review with a colleague.
  • Day 4 (1h) — Convert to PDF, combine attachments, upload, submit.

With engine — 8 hours

  • Overnight (0h) — Engine auto-downloads SOW + amendments + Q&A into the opportunity locker. Generates compliance matrix. Flags 2 gaps: expired COI, missing FCSI cert.
  • Day 1 (0.5h) — Open Submission Readiness page. See readiness score 76%. Email broker for COI renewal in one click (template pre-filled).
  • Day 1 (3h) — Click "Generate proposal" — engine drafts using vault's capability statement excerpts and tailored past-performance bullets. You edit for tone and add the win-strategy paragraphs.
  • Day 2 (2h) — Pricing model. Still human.
  • Day 3 (1.5h) — Red-team review. Still human.
  • Day 3 (0.5h) — COI uploaded by broker, vault auto-tags expiry. Compliance matrix flips green. Click "Generate Package" → ZIP downloads. Upload to SAM.gov.
  • Day 3 (0.5h) — Authorized signatory reviews + clicks Submit on SAM.gov. Engine prompts for confirmation #; stores against the opportunity.
Engine actions in detail (click to expand)
  • Attachment locker: GET api.sam.gov/.../v3/{noticeId} → downloads SOW.pdf, Amendment-1.pdf, QA-Round1.pdf. pdf-parse extracts text, cached on the row.
  • Compliance matrix: Claude reads parsed text + vault inventory. Returns JSON: [{requirement: "Past performance — 3 federal contracts within 5 years", required: true, evidence_id: doc-7, status: "satisfied"}, {requirement: "Active SAM registration", evidence_id: doc-12, status: "satisfied"}, {requirement: "FCSI certification", status: "gap"}, ...]. Persisted as a row in opportunity_compliance.
  • Submission package: assembles from approved OpportunityOutputs + evergreen docs flagged in the matrix. Markdown → PDF via documentRenderer. Streams a single ZIP back.
  • Mark-submitted: human uploads the agency confirmation; stored as an opportunity_attachments row with source=manual.

Use case 2 · Grants.gov application

Scenario: Federal AI workforce-training grant (NOFO from Department of Labor). Total budget $750k over 2 years. Application via Grants.gov Workspace. Deadline 30 days. Includes SF-424, SF-424A budget, project narrative, key personnel CVs, letters of support.

Today — 32 hours

  • Week 1 (5h) — Read full NOFO. Decide go/no-go. Identify the SF-424 family forms required.
  • Week 1 (2h) — Locate evergreen docs. Build compliance matrix.
  • Week 2 (10h) — Project narrative draft. Page-limited (typically 25 pages).
  • Week 2 (4h) — Budget Excel + budget narrative. Itemized.
  • Week 3 (3h) — CVs of key personnel updated for this grant.
  • Week 3 (3h) — Letters of support — chase 4 partner orgs.
  • Week 3 (2h) — Internal compliance review (institutional sign-off).
  • Week 4 (2h) — Workspace upload, validation, submit.
  • Week 4 (1h) — Track confirmation, document submission.

With engine — 16 hours

  • Overnight (0h) — Engine downloads NOFO + SF-424 family templates into the locker. Compliance matrix names every required form by SF number.
  • Day 1 (1h) — Review readiness page. 4 of 5 evergreen docs satisfied; 1 gap (DOL-specific organizational chart needed).
  • Day 1–2 (6h) — Click "Generate project narrative" — engine drafts from NOFO requirements + capability statement + past-performance vault. You edit extensively (this is the strategic core).
  • Day 3 (3h) — Click "Generate budget narrative" — engine produces first-pass budget table from labor categories in profile + scope. You adjust rates and itemize. Pricing decisions still human.
  • Day 3 (1h) — Engine pre-fills SF-424 form fields from vault. Human reviews and corrects.
  • Day 4 (3h) — Letters of support — engine drafts personalized request emails to partner orgs from your past performance log. You send. Partners still have to write the letters.
  • Day 5 (1.5h) — Red-team review.
  • Day 5 (0.5h) — Generate package, validate in Workspace, submit.

Why grants save fewer hours percentage-wise than SAM bids: grants are dominated by the project narrative, which is irreducibly strategic. The engine accelerates everything around it — forms, budget, evergreen attachments, compliance matrix — but the narrative itself still requires deep human thinking.

What we automate vs. what stays human

🤖 Engine handles

  • RFP attachment download — overnight, every active opp, every platform.
  • Document text extraction — pdf-parse + mammoth cache parsed text per attachment.
  • Compliance matrix generation — Claude reads RFP + vault + profile, returns JSON requirements list with evidence links.
  • Gap detection — what's missing, what's expiring, what to renew.
  • Drafting — proposals, cover letters, budget narratives, capability statements, resumes (already shipped) — grounded on real evergreen docs.
  • Format rendering — markdown to PDF and DOCX, agency-ready.
  • Package assembly — single ZIP with everything required for the upload.
  • Expiry alerts — daily email when a doc expires in <30 days. Reuses the v9.10 Source Health Agent email.
  • Mark-submitted bookkeeping — store the agency confirmation # against the opp.

👤 Human still owns

  • Win-theme strategy — what makes Colaberry the right pick for THIS RFP.
  • Pricing & labor rates — margin calls, competitive positioning, profit.
  • Solution design — what we'll actually build, who's on the team, what the approach is.
  • Red-team review — accuracy, tone, compliance, win probability.
  • Tailoring narratives to agency priorities — DHA cares about X, City of Houston cares about Y. Engine generates a base; humans adapt.
  • Letters of support, partner outreach — relationship work.
  • Authorized signatory's certification — the legal "I attest" at submit. Cannot be automated, by law.
  • The Submit & Finalize click — on SAM.gov, grants.gov Workspace, or Bonfire portal. ToS + accountability stay with a human.

  2. Phase 2 — attachment locker. Unblocks Phase 3.
  3. Phase 3 — compliance matrix. Now the page can show real readiness scores.
  4. Phase 4 — package assembler. End-to-end "ready package" flow live.
  5. Phase 5 — readiness page + expiry alerts. Operationalizes everything.
  6. Phase 6 — auto-fill from vault. Quality lift on top of working pipeline.

Per-phase exit criteria

Phase 1 — Vault
  • Migration runs clean; documents table has all enum values.
  • POST upload with PDF persists file to ./uploads/documents/<org>/<type>/<uuid>.pdf and creates a row.
  • GET expiring-within=30d returns rows with expires_at ≤ now+30d.
  • Re-upload bumps version 1→2, old version retained.
  • /admin/documents renders, expiry badges visible.
Phase 2 — Locker
  • For an existing SAM.gov opp, fetcher creates opportunity_attachments rows with on-disk files + non-empty parsed_text.
  • Same for a grants.gov opp.
  • For a known-clean Bonfire agency, detail-page fetcher produces ≥1 attachment.
  • Source Health page shows attachment-fetch stats per source.
Phase 3 — Matrix
  • For a known SAM.gov opp with a SOW PDF, complianceMatrix.runFor(opp) returns ≥10 rows.
  • Each row has requirement, required bool, status, evidence_id.
  • Re-running with no changes is idempotent (matrix stable; generated_at updates).
Phase 4 — Package
  • GET submission-package returns a ZIP with proposal PDF + linked evergreen + manifest.json.
  • Markdown proposal renders to a readable PDF (correct fonts, headings, line breaks).
Phase 5 — Readiness page + alerts
  • Per-opp readiness page renders with score + gaps.
  • Doc with expires_at = now+15d appears in next-day Source Health email under "Documents expiring soon."
Phase 6 — Auto-fill
  • Re-generated proposal contains specific phrases from uploaded capability statement (string-match against documents.parsed_text).
  • Output's metadata.evergreen_docs_used array contains the IDs that were injected.

Risks & open questions

RiskMitigationOwner
SAM.gov API tier — free tier is metadata-only; attachment URLs need paid tier or HTML scraping. Phase 2 implements both: try API first, fall back to HTML scrape of public detail page. Brittle but documented. Engine
Bonfire detail pages + Cloudflare — ~50% of agency portals throw a CF challenge. Same pattern as existing Phase B/C ingest: log blocks, never retry, accept partial coverage. Run twice/day. Engine
ToS exposure on auto-submit — clicking Submit in someone else's portal violates most ToS. Engine stops at "ready package." Human always clicks Submit. Hard product constraint. Product
Compliance matrix accuracy — Claude is good but not perfect on procurement parsing. Banner: "AI-generated; verify before submitting." Persist model + prompt version for audit. Human review
File storage durability — local disk in a Docker volume is fine for v1, not for compliance archives long-term. Plan S3 swap once we hit ~5GB or need redundancy. Storage adapter abstracts the swap. Future
Expired-doc false alarms — COIs and certs sometimes have rolling renewal past their printed date. Show the date, never auto-disable. Human always confirms. Human review
Authorized signatory — final certification at submit must be a legally authorized human. Hard constraint. Engine cannot impersonate. Document on every output. Legal
Scanned-image PDFs — pdf-parse misses image-only PDFs (older agency forms). v1 deferred. v2: add Tesseract OCR or AWS Textract if we hit them in real RFPs. Future

Glossary

UEIUnique Entity Identifier; replaced DUNS in 2022. Required for SAM.gov registration.
CAGECommercial and Government Entity code; assigned by DLA, used for federal contracting.
NAICSNorth American Industry Classification System; codes that classify your services. Drives federal eligibility.
NOFONotice of Funding Opportunity; the grant equivalent of an RFP.
