Submission Readiness v0.6 (Phase 6)

Auto-fill from Evergreen Vault · Walkthrough · 2026-05-08 · commit 5d0ab88

The proposal generator now reads the actual content of your vault docs (capability statement, past performance summaries, references) and feeds excerpts into the AI prompt. Generated proposals cite real org artifacts instead of inferring everything from JSON profile fields like services: ["ai-systems", "data-analytics"].

Lazy text extraction closes the gap for non-markdown vault docs: PDF + DOCX get extracted on first read via pdf-parse / mammoth, cached on documents.metadata.extracted_text for next time. Pure backend upgrade — no UI change. Quality multiplier on every proposal / offer / resume going forward.

Smoke verified on prod: for the existing capability statement in the vault, 1,500 chars of real markdown content ("## Core Competencies — Expertise in developing and implementing advanced Records Management Systems...") loaded ready for prompt injection.

What changed

Pure backend. No UI, no migration, no schema. Three additions to document.service plus a wiring change in actionGenerator:

  • getOrExtractText(doc) — reads vault file from disk, extracts via mime-appropriate parser, caches result on metadata.extracted_text.
  • loadVaultExcerpts({org, types, bonfireOpportunityId, caps}) — pulls vault docs of requested types, dedupes by type (bid scope > global), returns capped excerpts.
  • actionGenerator.generateOutput — calls loadVaultExcerpts per output type, injects via new appendVaultBlock helper into the prompt, persists audit on metadata.evergreen_docs_used.

Effect: every proposal / offer / resume generation now reads the org's actual material.

1 · End-to-end flow

What happens when you click ✍️ Generate Proposal on an opportunity row:

  1. Existing v8 lifecycle + grounding gates run as before.
  2. Past wins (last 5 approved proposals) load from pastWins.service.
  3. v0.6: vault excerpts load. For type=proposal, loadVaultExcerpts pulls capability statement + past performance + references docs. Local-to-bid takes priority over global on dedupe by type.
  4. v0.6: lazy extraction. Each picked doc's parsed_text comes from cache if present, otherwise pdf-parse / mammoth runs once + caches.
  5. System prompt + user prompt assembled. Vault excerpts appear under a new === Approved Source Material === block at the bottom of the user prompt.
  6. AI call (gpt-4o-mini, ~900 tokens). Generated content lands in OpportunityOutput as draft.
  7. v0.6: audit trail. metadata.evergreen_docs_used array records which vault docs informed this draft (id + type + scope + chars).

5 · Lazy text extraction (PDF + DOCX vault docs become readable)

Until v0.6, vault docs uploaded as PDF or DOCX were opaque to the AI — the system knew the file existed and counted toward readiness, but couldn't read the content. v0.6 adds a one-time extraction layer: 

// First read on a PDF vault doc:
const text = await getOrExtractText(doc);
// → loads file → pdf-parse → caches on metadata.extracted_text → returns text

// Second read on the same doc:
const text = await getOrExtractText(doc);
// → metadata.extracted_text exists → returns immediately, no fs read
  • PDF: pdf-parse (already installed for the v0.4 attachment locker).
  • DOCX: mammoth.extractRawText (already installed).
  • Markdown / text: plain utf8 read.
  • Other (images, etc.): returns null — doc skipped from prompt.

Extraction is cached on documents.metadata.extracted_text + extracted_at. Re-uploads bump the document version which gets a fresh extraction on first read.

6 · Caps + prompt budget

  • Per-doc cap: 2 KB of text — enough for a capability statement excerpt or a past-perf summary, not enough to overwhelm the prompt.
  • Total cap: 10 KB across all injected vault docs.
  • If multiple docs of the same type exist, the loader picks the most recent active one (bid scope wins over global).
  • Excess content is truncated — explicit cap, not a silent drop.

For a typical proposal call (~3500 tokens system + user prompt prior to vault), 10 KB of vault content adds ~2500 tokens. Total stays well under gpt-4o-mini's 128k context.
