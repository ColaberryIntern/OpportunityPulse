Submission Readiness v0.5 (Phase 4)

Package Assembler · Walkthrough · 2026-05-08 · commits 7632038 + 6a9ffd5

The readiness panel can now be turned into a real upload. One click on the new 📦 Generate Package button on the Bonfire detail drawer streams a single ZIP containing every vault doc (global + bid-local), every AI-generated draft also rendered to PDF, every fetched RFP attachment, plus a README cover page and a JSON manifest. End-to-end the engine moves from “track docs” to “deliver the bid.”

Smoke verified on prod: ZIP built for a real Bonfire opp (the JB Whitel roof project) in <1s, 32 KB total, 13 files including README.md, manifest.json, 6 markdown vault docs each rendered ALSO to PDF, and the historic References List PDF.

What changed visually

One new admin-only banner at the bottom of the Bonfire detail drawer:

  • 📦 Submission Package blue banner — explains what the package contains.
  • 📦 Generate Package button — clicks → backend streams a ZIP → browser saves it.
  • Filename: submission-package_<title-slug>_<date>.zip

No new pages, no new tables, no migration. Pure additive endpoint + UI.

Layout rules

  • /vault/global/ — evergreen docs reusable across bids (capability, references, etc.).
  • /vault/bid-local/ — docs specific to THIS bid (AI-generated cover letter, etc.).
  • Markdown source kept as .md; auto-rendered PDF emitted alongside so agency portals that demand PDF have one.
  • Existing PDFs (e.g. the References List PDF that was uploaded directly) flow through as-is, no re-render.
  • /attachments/ — empty in this smoke since Bonfire CF blocked the fetcher today; would contain RFP attachments otherwise.

5 · Markdown → PDF rendering

AI-generated docs are markdown. Many agency portals require PDF. The renderer walks markdown-it tokens and emits pdfkit drawing commands — no Chromium, no puppeteer, ~2 MB of pure-JS deps.

Supported markdown features:

  • # / ## / ### headings (font hierarchy preserved)
  • Paragraphs with bold, italic, inline code, and links
  • Bulleted (* / -) and ordered (1.) lists, single level
  • Horizontal rules (---)
  • Fenced code blocks (mono font, indented)

Output is a Letter-size PDF with 1-inch margins, body 11pt Helvetica, headings in the OIED navy. Procurement-portal acceptable for most cover-letter / capability / EEO / non-collusion / etc. types.

Trade-off

  • Lightweight by design — no Chromium means low memory footprint and fast cold start.
  • Complex markdown (tables, deep-nested lists, images) renders best-effort. If we hit cases requiring richer rendering, swap in a puppeteer pipeline later.
  • Headings are not numbered automatically; PDF has no clickable TOC. Both are easy adds in a future iteration.
PDF rendering feedback — quality concerns, missing markdown features?
